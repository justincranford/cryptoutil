## Phase 1: Define Kubernetes Deployment Contract

- Registry evidence is 7 PS-IDs + 3 products + 1 suite, not four products. Do not instantiate
  obsolete PKI as another product after consolidation into sm-kms. Use the three registered
  products as the explicit draft scope assumption; adding a fourth requires a defined
  identity/membership scope change, not guessed membership or a claim of user approval.
- Abstract identity is (run, tier, scope, mode, PS-ID, backend pool, ordinal). Define that
  taxonomy before enumerating resources; namespace, DB, SAN and config generation share it.
- Replica pools preserve legacy slots: two PG replicas and two independent SQLite replicas
  in mixed mode, not two replicas of each of the four existing slots.
- A second SQLite pod is independent data, not HA. Stable ordinal endpoints are necessary;
  routing independent databases through one pooled Service is a correctness bug.
- Effective product/suite Compose secret mounts share unseal/pepper at tier scope despite
  conflicting handbook prose. Migration must preserve HKDF inputs and imported material.
- Shared PostgreSQL logical follower is not a failover primary; wait for migrations before
  subscriptions, without making OLTP readiness depend on the follower.
- Zero-latency remote health cannot be stateless in the literal sense. Fast read-only
  handlers use bounded-freshness snapshots; monitoring state is explicit and testable.
- Admin loopback and mTLS require exec probes with the application's client binary, not
  kubelet HTTP probes or a newly exposed unauthenticated admin port.
- Deterministic generated names do not mean deterministic secret values or predictable
  controller UIDs. Expected inventory must distinguish active/min and reserved/max identities.
- Full matrix costs are derived, not guessed: `21 member occurrences * 7 pools across modes *
  2 pods = 294 app pods`. Local capacity failure must not silently weaken replica settings.
- See [design](k8s-design.md), [model](k8s-model.json), [tree](k8s-deploy-tree.md),
  [expected inventory](k8s-expected-inventory.json) and [tests](k8s-model_test.go).
- Human design review and Phase 2 runtime authorization are not complete or implied by this
  evidence. The review/authorization gate belongs to Phase 2; the main-agent Phase 1
  postmortem/acceptance remains pending user follow-up.
- Review passes covered source/registry fidelity, exhaustive graph/legacy-slot mapping,
  replica/SQLite semantics, probe transport and freshness, RBAC pod-versus-container
  boundaries, source-to-target data migration, deterministic output and triad consistency.
  Runtime and human-review tasks remain unchecked rather than borrowing prototype evidence.

### Phase 1 implementation worker notes (2026-11-01; preliminary, not the main-agent postmortem)

#### What Worked

- Named-file, build-ignored execution kept the planner outside normal package and coverage
  discovery while still allowing shuffled tests, vet, and measured 98.3% statement coverage.
- One pure inventory feeds deterministic Markdown and checked-in JSON. The default counts
  remain 55 releases, 147 pools, 294 application pod slots, 63 PostgreSQL databases, and
  84 active SQLite claims; the identity mixed-disk projection remains 1/10/20/5.

#### What Didn't Work

- Initial `-check` and `-write` status messages ignored stdout failures; a focused injected
  writer test reproduced exit status 0 instead of failure.
- Normal and tagged repository builds could not finish because required modules were not
  available during the initial configured-proxy attempt. A later unchanged build retry passed;
  no dependency or environment workaround was applied.
- The first commit-hook run reformatted the new expected JSON and exposed that
  generated bytes did not yet match the repository's sorted-key/two-space JSON format.

#### Root Causes

- `fmt.Fprintln` return values were discarded in the check/write status paths, unlike preview
  output. The CLI therefore claimed success despite a failed status write.
- The prior model parser did not reject duplicate JSON/YAML keys, non-object/null JSON,
  unknown registry fields, multiple YAML documents, and large unbounded expansions; DNS
  validation used an incomplete label rule and an arbitrary 200-byte suffix ceiling.
- The initial serializer emitted struct field order with four-space indentation;
  `pretty-format-json` sorts keys and uses two spaces, so it made an otherwise valid
  generated inventory fail exact-byte parity.

#### Patterns

- Test CLI output errors through injected writers and return nonzero for every failed output
  path, including success-status messages.
- Make deterministic generated JSON use the repository formatter's exact canonical key order,
  indentation, and newline; rerun artifact parity after formatter hooks.
- Strictly validate the complete input document before generation, validate fully expanded
  names, and preflight a documented capacity ceiling before enumeration without clamping input.
- Treat the model as the sole source for both human and machine-readable expected artifacts;
  compare/write both with exact-byte semantics and never put secret values in either output.

The final main-agent Phase 1 postmortem and acceptance decision are intentionally reserved for
the user follow-up; this note records worker findings, not human review or runtime authorization.
